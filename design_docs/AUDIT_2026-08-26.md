## 2. The refusal surface — the core argument for a front door

The transpiler refuses in **108 places** across four stages, but through only
**21 typed error variants**, and 76 of the 108 are a single variant carrying free
text:

| variant | sites | where |
|---|---|---|
| `UnsupportedConstruct` | 76 | chir/shir |
| `TickInsideBranch` | 8 | chir/shir |
| `UnresolvableType` | 6 | chir |
| `AmbiguousWidth` | 6 | chir |
| `NoTick` / `CrossClockTick` | 3 / 3 | shir |
| `RegisterWireConflict` | 2 | chir |
| `UnsupportedExpr` / `UnsupportedStmt` | 2 / 2 | parser |
| `VLIRLowerError::*` | 8 variants | vlir |

**This is the mechanism behind the "grouped by error message rather than
mechanism" failures** recorded in `TODO` for causes C, D and J: 76 distinct
refusals share one variant, so two unrelated blockers are indistinguishable to
anything but a human reading the string. A positive admissibility grammar
replaces the 76 with one enumeration.

```bash
grep -rn 'UnsupportedConstruct *{' --include='*.rs' copper-codegen/src copper-core/src | grep -v 'pub enum\|=> ' | wc -l
```

### 2a. The FIR mirrors Rust, not hardware

`copper-core/src/frontend_ir.rs:319` — `ExprType` has **33 variants**, including
`Yield`, `Try` (`?`), `Closure`, `Async`, `Reference`, `Macro`. Every downstream
pass carries match arms for constructs that can never be hardware. This is the
structural root of the bloat: the subset shrinks this enum, and the shrink
cascades through `parser.rs` (3,295 lines), `chir_lower.rs`, and the
exhaustiveness arms behind them.

## 5. Orphans and a fresh-clone failure

### 5a. Two tests depend on files that are not in git

`verilog/` and `cpp_testbenches/` are **untracked and not gitignored** (`.gitignore`
covers only `obj_dir*/` and `tb_*.cpp`). Four `.v` files there are referenced at
runtime by tracked code:

| file | referenced by | executes? |
|---|---|---|
| `verilog/hybrid_pipeline.v` | `tests/verilog_hybrid_pipeline.rs:39` | **yes** |
| `verilog/fifo_mem_new.v` | `tests/verilog_fifo_memory_new.rs:160` | **yes** |
| `verilog/inverter.v` | `copper-sim/src/testing.rs:22` | no — `rust,no_run` doctest |
| `verilog/jk_ff.v` | `copper-sim/src/testing.rs:45` | no — `rust,no_run` doctest |

So **`tools/regression.sh` does not pass on a fresh clone**: those two tests
`.expect()` the verification and would panic with the reference Verilog absent.
It fails loudly rather than skipping silently, which is the good half — but it is
the same class as the guards G-A..G-D exist to prevent, and no guard covers
"a referenced reference file is in version control".

Every other referenced `.sv` (26 of them, under `examples/**/sv/` and
`tests/fixtures/timing_probe_sv/`) is tracked and fine.

```bash
grep -rhoE '"[a-zA-Z0-9_./-]+\.s?v"' --include='*.rs' --exclude-dir=target . | tr -d '"' | sort -u | \
  while read p; do [ -f "$p" ] && (git ls-files --error-unmatch "$p" >/dev/null 2>&1 || echo "UNTRACKED $p"); done
```

## 6. Coverage — which compiler paths anything actually executes

Method: `cargo-llvm-cov` over **both** surfaces, because `cargo test` only *builds*
examples and would report every example-only lowering path as dead.

```bash
cargo llvm-cov clean --workspace
cargo llvm-cov --workspace --no-report --no-fail-fast
for ex in $(grep -A3 '^\[\[example\]\]' Cargo.toml | grep name | sed 's/.*= *//' | tr -d '"'); do
  cargo llvm-cov run --no-report --example "$ex"; done
cargo llvm-cov report --workspace --summary-only     # --workspace matters: without it
                                                     # the report covers only the root crate
cargo llvm-cov report --workspace --json --output-path cov.json
tools/coverage_audit.py cov.json "$PWD" dead.json          # per-file + dead-function ledger
tools/refusal_reachability.py cov.json "$PWD"              # which refusals can ever fire
```

The two helper scripts live in `tools/` for the reason `regression.sh` does: a
measurement that only exists in someone's scratch directory gets re-done by hand,
and then it goes stale. `coverage_audit.py` normalises Rust v0 mangling — the crate
disambiguator differs per test binary, so a naive count reports one function as dead
once per binary that happens not to call it (3,066 phantom "dead functions" before
normalisation, 404 after, and the residue is generic instantiations). **Trust the
region percentage, not the function count**: a file at 100% region coverage has no
dead code however many instantiation records show zero.

**The run was green**: every test passed and all 26 examples passed. So everything
below describes code that is not exercised, not code that is broken.

**Overall: 86.60% region coverage** (31,596 regions, 4,233 uncovered; 91.23% of
functions executed). That is high, and it confirms §4 from the other direction —
there is no large pool of dead code to sweep up.

| `copper-codegen/src/chir_lower.rs` | 81.5% | **1,368** |

### 6a. A second, obsolete Verilog emitter is still compiled in

`copper-codegen/src/verilog.rs` — **212 lines, 305 regions, 0% covered.** It is the
old `Module` → `IRBuilder::from_ast` → `VerilogGenerator` pipeline, entirely separate
from the current `transpile_fir` spine. The whole chain is dead:

| item | status |
|---|---|
| `copper-codegen/src/lib.rs:388` `pub fn to_verilog<M: Module>` | **no callers anywhere in the repo** |
| `copper-codegen/src/verilog.rs` (all of it) | reached only via `to_verilog` |
| `copper-codegen/src/parser.rs:49` `IRBuilder::from_ast` | reached only via `to_verilog`, and is a **no-op stub** already marked `// Is this a NO-OP rn? // TODO: Remove` — it returns an empty `ModuleIR` |
| `copper-core/src/lib.rs:119` `trait Module`, `FunctionAst` | the old front door |

Because `from_ast` returns an empty module, `to_verilog` does not merely go unused —
it would emit an empty module if called. **This is the single clearest deletion in
the codebase** and it is not a judgement call.

### 6b. Three quarters of the refusal sites are unreachable

Cross-referencing the 108 refusal sites from §2 against region execution counts —
i.e. "can any test or example in the corpus actually trigger this diagnostic?":

- **21 reachable**
- **60 unreachable** (covering region executes zero times)

concentrated as 52 in `chir_lower.rs`, 6 in `shir_lower.rs`, 2 in `vlir_lower.rs`.
(Counts shift by a few depending on how `Display`-impl arms are filtered; the ratio
is the signal, not the exact integer. Re-run with `tools/refusal_reachability.py`.)

Two coherent clusters stand out rather than a scatter:

- **~9 structural-module refusals** (`chir_lower.rs:1538-1658`) — every diagnostic
  for `#[hardware(structural)]` is untriggerable, because the mode has exactly one
  module (`two_domain_top`) and `build.rs`'s `SKIP` excludes it from the sweep.
  **Relevant to tomorrow**: if the pipelined CPU becomes a hierarchy of modules,
  it will be the first real exercise of a mode whose entire error surface is
  currently unexercised.
- **~8 memory refusals** (`chir_lower.rs:3986-4300`) — the `Memory` error paths are
  untested even though the happy path transpiles and is swept.

For the subset work this is the useful form of the §2 finding: the front door does
not need to replicate 108 refusals, because 60 of them have never fired.

### 6c. One suspicion, checked and dropped

I flagged `chir_lower.rs:1997` (`"clk.tick().await inside a for-loop (a counted
delay) is not yet supported"`) as possibly stale after cause M. **It is not stale** —
the covering region executes (count 1). Control extraction's `desugar_counted_loops`
handles the extracted path, and this refusal still guards the linear one.
